# 功能覆盖与边界检查

下列 32 个场景用于检验导航是否能覆盖不同日常用途，不证明理论穷尽，也不是自然语料。相同领域活动可能需要多个功能组合。

| 场景 | 主要条目 | 为什么不混淆 |
|---|---|---|
| 问路 | 询问信息 | 问路的内容不是独立语言行为；“能让一下吗”可能是行动请求。 |
| 核对预约时间 | 求证 | 核实时间不等于要求对方预约。 |
| 请求预约 | 请求 | 预约是一项领域活动；确认安排可用 accept-proposal/ratify-agreement。 |
| 提出新会议时间 | 提议方案 | 不是承诺所有人会参加。 |
| 还价 | 反提案 | 以已有价格条件为前项，不另设每个交易领域的叶。 |
| 答应送资料 | 答应请求 | 别把听懂资料要求的 acknowledge 判为答应。 |
| 主动承诺交付 | 承诺 | 不同于预计能交付 predict。 |
| 表示自己打算出国 | 表明打算 | 未必对听者负有履行责任。 |
| 拒绝邀请 | 拒绝行动 | 不是反对某个事实真假。 |
| 未听清再问 | 请求复述 | 声音问题与含义歧义不同。 |
| 询问术语所指 | 请求澄清 | 不是重新索取已有明确意思之外的新事实。 |
| 纠正日期事实 | 纠正事实 | 口误修复用 self-repair；新证据改判断不能混为口误。 |
| 为方案给出依据 | 论证 | 比较、因果分析是操作而非天然目的。 |
| 认为依据不足 | 质疑 | 不必已断言结论为假；可兼 ask-evidence。 |
| 指出他人失职 | 指责 | 批评作品质量不必给人归责。 |
| 正式举报侵害 | 提出侵害指控 | 提出指控不证明所指事实成立。 |
| 承认自己的错误 | 认错 | 不自动完成道歉。 |
| 向受影响者致歉 | 道歉 | 不要求对方原谅；原谅另用 forgive。 |
| 请求免除惩罚 | 请求宽宥 | 本人求饶与替他人求情归同功能，不用强度堆叶。 |
| 请求重审处罚 | 申诉复议 | 复核正确性不同于承认裁决后求从轻。 |
| 安慰失利朋友 | 安慰 | 安慰不等于劝其继续；后者可兼 encourage。 |
| 祝贺朋友毕业 | 祝贺 | 对未来好结果的希望是 wish-well。 |
| 发出威胁 | 威胁 | 须以自己一方所声称能施加的后果促服从，不能把一切风险告知算威胁。 |
| 许可请假 | 许可 | 普通建议不建立权限；需记录说话者资格。 |
| 授予代表签收权限 | 授权 | 许可与代理权限不同；不能只按“你可以”字面识别。 |
| 任命主持人 | 任命 | 提名推荐不等于正式任命。 |
| 宣布比赛开始 | 宣告状态 | 有权建立状态不同于告知别人已宣布。 |
| 把话轮交给下一位 | 交出话轮 | 仅点名不够，必须读上下回合。 |
| 要求继续说完 | 保持话轮 | 保持话轮不同于取得话轮。 |
| 反馈听懂但不同意 | 表示听懂 / 反对观点 | 理解反馈与观点接受是独立功能，可同时成立。 |
| 讨论后总结但未决定 | 收束要点 | 总结内容不等于 ratify-agreement。 |
| 暂缓采购决定 | 暂缓决定 | 暂停决策不要求 pause-dialogue。 |
